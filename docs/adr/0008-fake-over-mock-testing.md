# 8. 测试策略：全面使用手写 Fake 替代动态 Mock

- 状态: Accepted
- 日期: 2026-11-02
- 决策者: iOS 架构团队

## 背景与问题陈述

传统测试常采用运行时 Mock 工具或代码生成库，但这通常需要修改方法签名、增加宏编译时间，并且无法获得强类型编译期校验。

## 决策驱动因素

- 编译期强类型安全校验
- 行为可预测，与真实业务协议 100% 保持一致
- 测试代码更具可读性与自解释性

## 决策结果

选定选项：
- 全面禁止在项目中引入第三方运行时 Mock 框架；
- 在 `CoreTesting` 中统一收拢通用的 Fake 实现（如 `FakeNetworkClient`、`FakeStorage`）；
- 业务测试均手写基于协议的 Fake 对象，模拟各种成功与失败分支。
