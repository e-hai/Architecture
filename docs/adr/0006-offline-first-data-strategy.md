# ADR-006: 采用离线优先数据策略

## 状态

Accepted

---

## 背景

移动网络环境不稳定，用户可能在无网络连接时使用应用。需要保证数据在任何网络条件下的可访问性和一致性。传统的「在线优先」策略在网络不可用时无法显示数据，用户体验差。

## 备选方案

- **在线优先**：每次请求优先访问网络，网络不可用时显示空状态或错误。用户体验差，离线不可用。
- **离线优先（本地为 SSOT）**：本地数据库是唯一真相来源（Single Source of Truth），UI 始终从本地读取数据，网络数据写入后通知本地更新。网络仅作为数据同步通道。
- **缓存优先**：先读缓存再读网络，但缓存不是 SSOT，可能产生数据不一致。

## 决策

采用离线优先策略。核心模式：

```
UI (Flow 订阅) → Repository → Room (SSOT) 
                           ↘ Network (同步通道)
```

流程：
1. UI 通过 Flow 订阅 Repository 暴露的数据流
2. Repository 从本地 Room 数据库读取数据并暴露为 Flow
3. Repository 提供 suspend 方法触发网络刷新
4. 网络数据到达后通过 DTO → Entity → 领域模型的映射链路写入 Room
5. Room 的 Flow 自动推送更新给订阅的 UI

数据转换遵守三模型分层：
- 网络 DTO（`core/network/model/`，`*Response` 后缀）→ 领域模型
- 数据库 Entity（`core/database/model/`，`*Entity` 后缀）→ 领域模型
- 领域模型（`core/model/`，无后缀）在模块间传递

## 理由

- 离线可用：用户在任何网络条件下都能看到数据
- 一致的读写路径：数据始终通过统一的持久化层流动
- 响应式更新：Room 的 Flow 在数据变更时自动通知 UI
- 数据可靠性：本地持久化防止数据丢失
- 网络波动容忍：异步刷新机制，不因网络失败影响 UI 展示

## 影响

### 正面影响

- 完全的离线可用性
- 数据一致性保障（单一真相来源）
- 自动数据刷新机制
- 所有数据层组件职责清晰

### 负面影响

- 需要维护三层模型转换映射（DTO/Entity/领域模型）
- 数据时效性需要额外处理（如显示"上次刷新时间"、后台周期性同步）
- 写操作复杂：需要同时更新本地和远程（最终一致性）
- 增加数据同步冲突处理的复杂度（如 Last-Write-Wins 策略）

### 中立影响

- Repository 使用 Flow + suspend 组合，同步与响应式分开
- 错误处理使用 sealed class Result 封装，禁止返回 null

---

## 遵循情况

- Repository 必须组合 Remote + Local 数据源
- DTO/Entity 必须通过 Mapper 转为领域模型，禁止在模块间直接传递
- UI 层禁止导入 Retrofit 或 Room 相关依赖
- 数据流必须使用 Flow（读取）+ suspend（写入）模式
